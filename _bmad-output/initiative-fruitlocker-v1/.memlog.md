- (requirement) R1 (brief Success Criteria, Compatibility): a pinned set of public Compose sample projects runs unchanged with docker compose up, down, logs and exec; the pass rate is published and is at least 80%.
- (requirement) R2 (brief Success Criteria, Compatibility): the core docker CLI commands work against fruitlocker: run, ps, logs, exec -it, build, pull, push, images, volume, network, inspect, stop, rm; each has a passing compatibility test.
- (requirement) R3 (brief Success Criteria, Compatibility): CI generates a public compatibility matrix against the pinned Apple container version.
- (requirement) R4 (addendum Minimum Engine API): the daemon serves /_ping, /version and /info with API version negotiation on a local Unix socket.
- (requirement) R5 (addendum Minimum Engine API): containers support create, start, stop, wait, stats and archive through the Engine API.
- (requirement) R6 (addendum Minimum Engine API): container logs, attach and exec work, with HTTP hijacking and TTY resize.
- (requirement) R7 (addendum Minimum Engine API): images support pull, push, tag, load and save, and /auth validates registry credentials.
- (requirement) R8 (addendum Minimum Engine API): /build works with BuildKit progress; subject to the build spike outcome, which may amend the gate.
- (requirement) R9 (addendum Minimum Engine API): networks and volumes work, with labels and filters.
- (requirement) R10 (addendum Minimum Engine API; brief The engine): /events streams container, image, network and volume state changes, built by polling Apple until apple/container#484 lands.
- (requirement) R11 (brief The engine): restart policies and healthchecks behave as Docker does, though Apple's runtime has neither.
- (requirement) R12 (brief The engine): containers on a Compose network reach each other by service name and alias over DNS.
- (requirement) R13 (brief Scope, Out by constraint): host networking, container: network mode, shared PID or IPC, Docker-in-Docker, host privileged mode and device passthrough each fail with a clear error, never silently.
- (requirement) R14 (brief The app): a native SwiftUI app with a menu-bar presence starts and stops the engine and shows containers, images, volumes and networks grouped by Compose project.
- (requirement) R15 (brief The app): the app streams a container's logs and opens a shell in it.
- (requirement) R16 (brief The app): on first run the app points the user's docker context at fruitlocker's socket, with an undo.
- (requirement) R17 (brief Scope, In v1): fruitlocker ships as a signed, notarized direct download and a Homebrew cask.
- (requirement) R18 (brief The experience): a user installs the signed app, opens it, runs docker compose up in an existing project, and it works.
- (constraint) Apple silicon on macOS 26 and later only; no Intel, Linux or Windows hosts (brief Scope, Platforms).
- (constraint) Built on the ContainerAPIClient XPC seam at apple/container 1.7.1; no parsing of container CLI output (brief What Makes This Different; addendum Technical constraints).
- (constraint) Apache-2.0, and every dependency Apache-2.0-compatible (brief Scope, In v1).
- (constraint) No Mac App Store or sandboxed distribution; no paid tier, accounts, telemetry or hosted services (brief Scope, Out of v1).
- (constraint) No Docker trademarks in the name or branding; Docker-compatible is the most it says (brief Scope, Out of v1).
- (constraint) The v1 architecture spine (AD-1 to AD-21) is binding; epics implement it and never re-decide it (architecture-fruitlocker.md).
