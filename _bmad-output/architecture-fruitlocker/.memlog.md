- (decision) Paradigm: hexagonal core (Docker domain model + ports) with reconcile-loop controllers; Swift 6 actors. Binds all daemon modules. Prevents adapters reaching into each other and controllers each polling Apple.
- (decision) Process topology: fruitlocker.app (UI), fruitlockerd (per-user LaunchAgent via SMAppService), fruitlocker-helper (root LaunchDaemon via SMAppService). Daemon runs without the app open. Prevents engine lifetime tied to the UI.
- (decision) Single apiserver client: only fruitlockerd links ContainerAPIClient. App and helper never talk to container-apiserver. Prevents two writers of Apple state.
- (decision) [ADOPTED by Josh] State ownership: daemon store owns Docker desired spec (config, restart policy, healthcheck, networks+aliases, names, Docker IDs, labels); apiserver owns runtime status, always read live. Apple container materialized at docker start from spec; pre-start edits (network connect, rename) change spec only. Apple objects carry back-reference label only. Prevents two sources of truth for one container.
- (decision) IDs: daemon mints 64-hex Docker IDs for containers, networks, volumes; Apple object id derived as fl-<first 12 hex>; Docker names live in the spec only. Prevents rename breaking Apple identity and ID-format drift.
- (decision) Images: Apple image store is the only image store; Docker image ID = Apple image config digest; daemon stores no layers. Prevents a second content store.
- (decision) Events: one in-process EventBus. A mutation the daemon performs emits its event at the mutation point; the runtime poller diffs apiserver snapshots and emits only for changes the daemon didn't cause. Controllers subscribe; none poll apiserver themselves. Prevents duplicate or missing /events.
- (decision) Mutation path: HTTP handlers call core services only; core services are the only callers of the AppleRuntime port; one actor per object kind serializes mutations. Prevents racing writes.
- (decision) [ADOPTED by Josh] DNS helper hands over sockets: root helper only binds <gateway>:53 and passes the bound fd to fruitlockerd over XPC; daemon parses/answers/forwards all packets; helper closes on daemon request or daemon death. Root never parses guest traffic. Needs a check that fd passing works with SO_REUSEADDR binds.
- (decision) Network lifecycle owned by one NetworkController: orders first starts, drives DNS bind/release per #5 guard, and owns #8 (apple/container#2051) detection/mitigation. Docker 'bridge' maps to a fruitlocker-owned Apple network, never Apple's 'default'.
- (decision) Unsupported-by-constraint options (host network, container: netns, shared PID/IPC, privileged host, devices, DinD, network connect on a running container) fail with an explicit error; never silently ignored. Unimplemented endpoints return 501.
- (decision) [ADOPTED by Josh] HTTP: Hummingbird 2 on SwiftNIO, Unix socket; hijacked endpoints (attach, exec start, build session) drop to a raw NIO channel handler. Hijack fit unverified.
- (decision) Registry credentials: daemon never persists credentials; X-Registry-Auth used per request; /auth validates only.
- (decision) Single extension namespace: app talks to fruitlockerd over the same socket, Engine API for Docker objects plus /fruitlocker/v1/* for engine-only concerns. No second app-daemon channel.
- (decision) Docker context: create/own a context named fruitlocker; never edit other contexts or DOCKER_HOST; first-run switch records the previous context for undo.

- (decision) [ADOPTED by Josh] A spec change Apple can't apply in place on an already-materialized container (networks, mounts, env, ports) recreates the Apple container on next start, losing its writable layer; response Warnings and a Type=daemon event say so.

- (decision) Three state classes: spec (desired), observed (daemon-observed: health, restart count/backoff, manuallyStopped, generation, runEpoch, last exit, allocated host ports; one named owner per field), runtime (live from Apple). Prevents health/RestartCount having no home.
- (decision) Materialization write order: spec pending, then Apple create, then mark materialized. Created at first start, reused after; specHash marks needsRecreate.
- (decision) Concurrency: per-object async FIFO mutex held across awaits; cross-kind references are FK rows checked and written in one FLStore transaction; lock order network, volume, image, container. Swift actors are reentrant, so per-kind actors alone don't serialize.
- (decision) Events: intent ledger with generation tokens; events published only after runtime success and store commit; emitter table names one emitter per (Type, Action); bounded history buffer in EventBus for since=; host network observations go on the bus via HostNetObserver.
- (decision) NetworkLifecycle port: every core start/stop awaits willStart/willStop before the runtime call; continuous backstop releases on unexpected last-container die, bridge-down, or mDNSResponder dropping udp4 *:53. Residual crash-exit window accepted.
- (decision) fd handover ownership: helper closes its copy right after handover, keeps no state, runs no guard; daemon is sole owner; release = daemon closes fd. FLDNS behind a DatagramSocket port so packet relay can replace fd handover.
- (decision) Security: Unix socket only, 0600 in a 0700 dir, never TCP; helper and daemon verify each other with XPC peer code-signing requirements (Team ID + bundle id); helper binds only a current vmnet bridge IPv4; v1 is single-user.
- (decision) Bootstrap exception to AD-2: the daemon may run 'container system start' (with kernel install) only to bring Apple's services up; output never parsed.

- (decision) Migrations: GRDB DatabaseMigrator, append-only named, run at boot after a file copy; store newer than binary refuses.
- (decision) Ports: Apple runtime publishing at materialization; requested bindings in spec, ephemeral host ports allocated by daemon at start into observed state; published ports land on the container's first network.
- (decision) Volumes: Apple volume store is the only volume store; keyed by Docker name; Apple id fl-<12 hex of sha256(name)>.
